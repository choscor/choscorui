# FFI safety record

## macOS bootstrap

`choscorui-macos` currently binds a small AppKit and Objective-C runtime surface by hand. The ABI shapes and numeric constants were checked against the installed macOS SDK headers on 2026-09-20 (`NSApplication.h`, `NSWindow.h`, `NSGraphics.h`, `NSRunningApplication.h`, and `objc/message.h`). Apple silicon runtime smoke testing succeeded. On 2026-10-08 the x86-64 slice of the universal archive ran under Rosetta 2. It crashed in `Window::set_accessibility`, because `convertRect:toView:` and `convertRectToScreen:` returned a 32-byte `NSRect` through plain `objc_msgSend`. Both helpers now use `objc_msgSend_stret` on x86-64. A rerun under Rosetta could not complete because Rosetta stopped starting AppKit processes after a debugger session, so the fixed path waits on the `macos-15-intel` CI job for its runtime check. [Apple's NSApplication reference](https://developer.apple.com/documentation/appkit/nsapplication) and [NSWindow reference](https://developer.apple.com/documentation/appkit/nswindow) define the intended platform behavior.

| Object or boundary | Ownership and lifetime | Thread rule |
| --- | --- | --- |
| `NSApplication sharedApplication` | Process singleton, never released by Rust. `Application` is a non-owning handle. `setActivationPolicy:` (Regular, `NSUInteger` 0, returns `BOOL` as `i8`) may refuse a redundant switch when launched from an app bundle, so a refusal is an error only if `activationPolicy` (returns `NSUInteger`) is still not Regular. | Construct and use on the process main thread. |
| `NSWindow alloc/initWithContentRect:...` | Returns +1 retained object. `setReleasedWhenClosed:NO` prevents `close` from releasing it. Rust `Window::drop` closes then releases once. | All methods and Drop stay on main thread; the safe type is `!Send`/`!Sync`. |
| `NSAutoreleasePool alloc/init` | +1 pool drained by local RAII guard. Autoreleased `NSString` values do not outlive each call. | Created and drained on the same thread. |
| `NSString stringWithUTF8String:` | Autoreleased; `setTitle:` copies/retains it before the local pool drains. NUL-containing Rust strings are rejected. | Used on main thread with the window. |
| `NSPasteboard` text access | `Clipboard` retains the class-method pasteboard result. Temporary named boards call `releaseGlobally` before releasing; the general pasteboard is never released globally. Each read/write creates a local autorelease pool and copies UTF-8 before it drains. `NSPasteboardTypeString` is an SDK-owned constant. Writes validate embedded NUL before clearing contents. | Safe handle is `!Send`/`!Sync`; construction rejects worker threads. A temporary board is used for the opt-in smoke test, leaving the general clipboard untouched. |
| `NSAlert`, `NSOpenPanel`, and `NSSavePanel` | Alert construction returns a +1 object held by a Rust RAII guard. Panel class methods and all strings, arrays, and URLs are autoreleased within the call's local pool. Selected URL paths are copied into owned `PathBuf` values before the pool drains. Inputs reject embedded NUL; extension filters also reject separators and leading dots. | Calls require an `Application` main-thread handle and run AppKit's synchronous modal loop. Cancellation returns a typed response instead of an error. Physical interaction and sandbox entitlement behavior still require manual verification. |
| `objc_msgSend` casts | Each cast uses the corresponding SDK argument and return ABI, including `NSRect` by value and Objective-C `BOOL` as `i8`. Raw IDs stay private to the crate. | Never invoked from worker-facing safe handles. |
| `NSView frame`, `NSWindow backingScaleFactor`, `convertRect:toView:`, `convertRectToScreen:` | Window owns the content view. Every `NSRect` return (`send_rect`, `send_rect_rect`, `send_rect_rect_id`) uses `objc_msgSend` on arm64 and `objc_msgSend_stret` on x86-64; `CGFloat` is double on both. Smaller structs (`NSPoint`, `NSSize`, `NSRange`) return in registers on both. | Queried on main thread. Intel runtime check: the `macos-15-intel` CI job. |
| Core Foundation run-loop source | `Application` owns the +1 source and removes, invalidates, and releases it on Drop. An Arc strong count keeps callback context alive through the final callback. | Workers signal through `Poster`; source callback executes queued tasks on main thread. A mutex excludes worker signals during teardown. |
| `NSWindowDelegate` runtime class | One registered Objective-C subclass handles resize, scale, focus, and close selectors. Each window owns a +1 delegate because `NSWindow.delegate` is weak. Drop closes the window, sets the delegate to nil, unregisters its queue, then releases delegate and window. Failed class construction disposes the unregistered class. | AppKit calls it on main thread. Each callback copies data into an owned Rust queue and contains Rust panics before returning to Objective-C. |
| `NSView` runtime subclass | A window retains its custom flipped content view. Rust releases the temporary +1 creation reference after `setContentView:`. The view accepts first responder and maps native mouse, wheel, key, and `NSTextInputClient` data into owned `WindowEvent` values. Marked text, selected/replacement UTF-16 ranges, commit/unmark, candidate-window rectangles, and character-index queries cross the FFI boundary as owned values. `interpretKeyEvents:` runs without holding the Rust event-queue lock; an ordinary-character fallback runs only when no text callback was produced. Precise scroll deltas retain point units; coarse deltas retain line units. | AppKit calls the view on the main thread. Every callback catches Rust panics, copies borrowed strings before returning, and looks up queue/text state by the owning window. Native smoke tests invoke marked and committed Japanese text callbacks directly. |
| `NSView drawRect:` and Core Graphics | The callback borrows the current `NSGraphicsContext.CGContext` only during drawing. Each window owns a shared display list; the callback clones it before painting. Colors, gradients, and images are tagged sRGB (`CGColorSpaceCreateWithName(kCGColorSpaceSRGB)`, one process-lifetime +1 reference). Paths, strokes, `CGGradient`, clip paths, and transforms map one-to-one onto display commands; each push maps to exactly one `CGContextSaveGState`, and group opacity uses a transparency layer. Shadows draw a core-generated mask (`Shadow::mask`) through `CGContextClipToMask`, so they match the software renderer. No CGContext escapes into safe APIs. | Main-thread only. `set_display_list` diffs the old and new lists (`choscorui_core::damage`) and calls `setNeedsDisplayInRect:` with the changed region only; an identical list schedules nothing, so an idle window never draws. |
| Image cache and ImageIO | `cg_image` copies straight RGBA pixels into a premultiplied +1 `CGImage` held by `CfOwned`. A thread-local cache keyed by `Image::id` holds up to 256 images and is cleared when the last window is dropped. `decode_image` wraps input bytes in a +1 `CFData`, decodes frame 0 with `CGImageSource`, and redraws it into an sRGB bitmap so embedded profiles are converted; images over 64 Mpx are rejected. `encode_png` writes into an owned mutable `CFData` and copies the bytes out before release. | Decoding and encoding are thread-agnostic and create their own autorelease pool; painting with cached images is main-thread only. |
| Cursors, capture, and occlusion | `resetCursorRects` adds one cursor rect for the view bounds. Standard cursors are NSCursor class singletons. Custom cursors build an autoreleased `NSImage` from a `CGImage` and an autoreleased `NSCursor`; the cursor rect retains it. Images over 256 points or hotspots outside the image are rejected. `Window::capture` uses an autoreleased `bitmapImageRepForCachingDisplayInRect:` and `cacheDisplayInRect:toBitmapImageRep:`, then copies the rep's `CGImage` into an owned sRGB `Image`. `windowDidChangeOcclusionState:` queues `WindowEvent::Occluded`. | Main thread. The smoke test checks idle paint counts, damage rectangles, captured pixel colors, and cursor validation. |
| Core Text line shaping and drawing | UTF-8 text/font names become owned CF strings, then a font, attribute dictionary, attributed string, and line. Each Create result is released by Rust RAII; `ShapedLine` owns the line used for metrics, caret offsets, hit testing, and `CTLineDraw`. `WrappedText` keeps its attributed text and font alive while a +1 typesetter suggests UTF-16 break counts; Rust maps them back to grapheme boundaries. The context is flipped around the logical baseline; the text matrix is restored explicitly because graphics-state save/restore does not cover it. | Drawn on the main thread inside `drawRect:` and in offscreen Core Graphics bitmaps. Fixtures cover advance/end-caret agreement, combining/emoji boundaries, RTL caret direction, word wrapping, CRLF, glyph ink at 1x/2x, and clipping. Mixed-direction affinity and wrapped selection remain open. |
| Core Text layout (`CoreTextShaper`) | Per paragraph, Rust creates +1 font (with symbolic traits and an optional `kCTFontCascadeListAttribute` descriptor copy), paragraph style, attributes dictionary (retaining `kCFType` callbacks), attributed string, and typesetter; each line is a +1 `CTTypesetterCreateLine` result. Glyphs, positions, advances, string indices, run status, and each run's resolved font name are copied into owned `GlyphRun` values before release, so no Core Text object outlives `shape`. Caret stops use `CTLineGetOffsetForStringIndex`; RTL lines align with `CTLineGetPenOffsetForFlush`. Painting re-creates fonts by PostScript name in a 64-entry thread-local cache and draws with `CTFontDrawGlyphs` on a baseline-flipped context. | `shape` is thread-agnostic; painting is main-thread or offscreen. Tests cover Vietnamese, CJK, emoji ZWJ/flags/skin tones, combining marks, Hebrew, Arabic, system and explicit fallback, bold/italic faces, wrapping, and painted-ink agreement with measured lines at 1x and 2x. |
| Typed pasteboard payloads and drag-and-drop | `pasteboard.rs` maps core formats to UTIs (`public.utf8-plain-text`, one `public.file-url` item per file, `public.png` with `public.tiff` read fallback, `public.url`, and `com.choscorui.private.<name>`). Writes build +1 `NSPasteboardItem`s owned by `CfOwned`, pass them in a +1 CF array to `writeObjects:`, and copy every string and `NSData` out before the local pool drains. File paths are returned precomposed (NFC). The content view implements `NSDraggingDestination`: callbacks look up per-window drop formats and operations, intersect them with the source mask, negotiate through `choscorui_core::negotiate_drag`, queue `WindowEvent::Drag`, and read payloads only in `performDragOperation:`. As `NSDraggingSource` it reports the operations given to `Window::begin_drag` and queues `WindowEvent::DragEnded`. `begin_drag` requires the current event to be a left mouse-down/drag in this window. | Main thread. Every callback catches panics and returns `NSDragOperationNone`/NO on failure. The smoke test drives the real destination callbacks with a synthetic `NSDraggingInfo` class (`simulate_external_drag`, hidden test support). Starting a drag session needs a physical mouse gesture and is a manual check. |
| Core Graphics bitmap context | `MacBitmap` creates a +1 sRGB bitmap context, releases it through Rust RAII, and copies each row before the context frees its backing memory. It validates row stride and total length before raw slice access. | Offscreen rendering has no AppKit window dependency. Pixel tests verify top-down RGBA row ordering. The facade's `render_parity` test renders every vector fixture through both `MacBitmap` and the software `Raster` at 1x and 2x and requires fewer than 0.5% of pixels to differ by more than 24 per channel. |
| Core Foundation one-shot and repeating timers | A Rust `Timer` owns the +1 `CFRunLoopTimer` and boxed callback context. Drop removes, invalidates, releases, then frees context. The context holds a weak reference to its owner; callback upgrades it so cancellation or dropping a handle inside the action cannot free context mid-callback. Application teardown cancels all surviving timers. Repeating timers keep their `FnMut` in the context between ticks and restore it only while still active, so canceling inside the callback stops delivery. Timers and the posted-work source are added in `kCFRunLoopCommonModes`, so they run during live resize, menu tracking, and modal panels. | Created, fired, canceled, and dropped on the main thread. Callback catches Rust panics. Equal-deadline timers and timers ready with posted work have no promised relative order. |
| System appearance and accessibility display options | `preferences.rs` reads `NSWorkspace.sharedWorkspace` `accessibilityDisplayShouldReduceMotion` / `accessibilityDisplayShouldIncreaseContrast` (BOOL getters) and `NSApp.effectiveAppearance.name`, copying the name into a Rust `String` inside a local autorelease pool. No objects are retained past the call. | Main thread. `macos/tests/preferences.rs` resolves the returned preferences through `ThemeResolver`. |
| Accessibility announcements and collection attributes | `Window::announce` builds an autoreleased `NSDictionary` (`NSAccessibilityAnnouncementKey` → `NSString`, `NSAccessibilityPriorityKey` → `NSNumber`) inside a local pool and posts `NSAccessibilityAnnouncementRequestedNotification` on `NSApp` via `NSAccessibilityPostNotificationWithUserInfo`. Element updates set `accessibilityRowCount`/`ColumnCount`/`Index` with `NSInteger` arguments (saturated from `usize`) and use `NSAccessibilityTextAreaRole` for multiline text. | Main thread. `window_smoke` reads back row count, index, and AXTextArea from the native elements. Whether VoiceOver speaks an announcement is a manual check. |
| Window placement, screens, and context menus | `window_state.rs` reads `NSWindow.frame`, `isZoomed`, and `styleMask` (full-screen bit 14). It writes with `setFrame:display:` (NSRect, BOOL), `zoom:` and `toggleFullScreen:` (nil sender). Global coordinates are flipped against the height of `+[NSScreen screens][0]`. `screen_visible_frames` walks the autoreleased `screens` array inside a local pool. `ContextMenu` owns a +1 `NSMenu` (with `autoenablesItems` off) and a +1 target object. Items are created +1, added to the menu, then released, so only the menu retains them. `Window::show_context_menu` calls `popUpMenuPositioningItem:atLocation:inView:` on the flipped content view; the menu and target outlive this synchronous tracking loop. Drop removes the target binding before releasing. | Main thread. The activation callback catches panics. `window_smoke` round-trips geometry through `set_geometry`/`geometry` and drives context-menu items through the native target/action. Real menu tracking needs a user and is a manual check. |
| Desktop integration | `desktop.rs` registers `ChoscoruiV2AppDelegate`. One instance is created per process and intentionally never released, because NSApplication and UNUserNotificationCenter hold their delegates weakly. It is installed before `finishLaunching`, so launch-time open-document events are delivered. Callbacks copy NSURL paths and strings into Rust before returning, and queue `AppEvent`s behind a `Mutex`. Completion-handler blocks passed in by the system are invoked through the block ABI's `invoke` pointer: exactly once in `didReceiveNotificationResponse`, and with presentation options in `willPresentNotification`. The authorization callback is a Rust-built global block (`BLOCK_IS_GLOBAL \| BLOCK_HAS_SIGNATURE`, isa `_NSConcreteGlobalBlock`, no captures) that writes an `AtomicU8`, so it is safe to call from any queue. `StatusItem` retains its `NSStatusItem` and owns its `ContextMenu`, so the item's action target outlives every click; drop clears the menu, calls `removeStatusItem:`, then releases. UserNotifications calls are gated on `NSBundle.mainBundle.bundleIdentifier`, because the framework raises an Objective-C exception in unbundled processes. `UNMutableNotificationContent` is created +1 and released after `addNotificationRequest:`. | Main thread, except the authorization block, which runs on a system queue. Callbacks catch panics. `window_smoke` drives the delegate's open-URLs and reopen methods, the status-item title and menu, URL-handler lookup, the unknown-scheme error, and the unbundled notification error. Posting and clicking a real notification needs a signed bundle and is a manual check. |

The Core Foundation source callback is `extern "C"` and catches Rust panics around each posted task before returning to C. It increments a count and continues later tasks. `Poster::request_stop` posts `NSApplication stop:` to the same thread. AppKit window and view callbacks are also `extern "C"` and catch Rust panics while queuing owned events. Timer callbacks also contain panics. Objective-C exceptions are not caught; the current selectors are called only with validated inputs. The smoke test is opt-in with `CHOSCORUI_RUN_MACOS_SMOKE=1` because it creates real OS windows. It verifies construction, title, visibility, content resizing, scale query, resize/close events, two-window event isolation, close/reopen, invalid size/title, worker-thread rejection, FIFO posted work on the UI thread, timer delivery and cancellation, native mouse/key callback translation, coarse and precise scroll units, `drawRect:` invocation, panic containment, native loop stop, and rejection after teardown. Direct view callbacks cover exact coordinate/modifier mapping; synthetic pointer and key events sent through `NSWindow` during `Application::run` verify window routing. Physical devices, on-screen pixels, IME, and display migration remain unverified.
