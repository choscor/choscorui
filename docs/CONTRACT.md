# Initial contracts (experimental)

This document records phase 0 decisions for the first prototype. The public API is experimental until two platform backends validate it.

## Support target and dependency policy

- Target macOS 15+ on Apple silicon and Intel first. Windows 11 on x86-64 follows. Linux targets current Wayland and X11 desktops on x86-64; exact distributions and runtime library versions require backend validation. These are development targets, not claims of support.
- Minimum Rust version is 1.85, using edition 2024. Runtime code uses `std` and system SDK FFI only. Build and test code follows the same rule initially. Any exception requires an explicit dependency policy revision and license review.
- First window types: one or more ordinary resizable top-level windows and transient dialogs. Sandboxed distribution is in scope for release, with platform-specific portal and entitlement behavior to be specified when those backends exist.
- The toolkit supplies desktop UI, not general application services. Networking, SQL, multimedia, web content, PDF, 3D, mobile/embedded targets, and visual designer tooling are outside 1.0 scope. Printing is deferred. Structured data and state machines remain application concerns unless a UI-specific need emerges.

## API direction

The experimental `choscorui` facade is the application-facing safe Rust API. It re-exports a curated set of retained-tree, composition, control, style, semantics, and display-list contracts; on macOS it also exposes `Application`, `Window`, menus, clipboard, timers, and owned native events. `Application` owns the UI thread and event loop, and `Window` pairs native window state with application-owned retained state. `Node` aliases stable, non-reused `NodeId`, `Theme` aliases resolved `DesignTokens`, and `Event` owns platform-independent pointer, key, or text input. The facade does not expose native handles. Its names and module layout remain unstable until another platform validates the contracts.

`choscorui-controls` has experimental `Button`, `Checkbox`, text `Label`, `Separator`, single-line `TextField`, integer `Slider`, integer `SpinBox`, and determinate/indeterminate `ProgressBar` behavior. They expose semantic role/name/value/state and independent actions where applicable; separate styles paint visual state. The text field uses `TextBuffer` for grapheme-safe insertion, deletion, selection, movement, undo/redo, and distinct edit/commit events. A common trait across all controls or styles remains deferred until concrete implementations demonstrate a useful shared contract.

`CommandRegistry` owns enabled/checked state by `CommandId`; the gallery stores its selected theme there. A command-bound button reads the current enabled state for input, appearance, and semantics without a manual sync call; input delivery cancels a pending press when the command becomes disabled. Shortcuts have application, window, and focused-node scopes with focused-first priority; duplicate chords in one scope fail, and a disabled winner consumes its chord. The gallery binds Control-Enter to its theme command. The macOS backend accepts an owned menu projection keyed by opaque command identities, installs a native AppKit main menu, updates title/enabled/checked/shortcut state, and returns native selections through an ordered activation queue; applications map those identities to their command registry. It also exposes synchronous application-modal AppKit alerts and open, multiple-open, directory, and save panels. Dialog cancellation is a successful typed response; native failures remain errors. Alert button results preserve declaration order, and file filters use extensions without leading dots. Window-modal sheets, color/font/input dialogs, and toolbar views remain open. Worker threads may enqueue posted work but cannot mutate the tree. Timers enqueue the same way and cancellation prevents future delivery. Models expose stable item identities, incremental changes, and selection independent of view nodes. Resource lookup returns an explicit missing-resource error; localization and theme changes invalidate affected measurement, paint, and semantics. Files, sockets, serialization, and general task execution remain ordinary Rust application code.

`ThemeResolver` resolves application tokens, ancestor scopes, then a node override. Tokens cover background/surface/content/accent/danger colors, typography size, spacing, radius, border width, elevation, contrast, and motion/reduced-motion policy. `AccessibilityPreferences` is applied last: high contrast selects the high-contrast token mode, reduced motion makes transitions immediate, and text scale multiplies the resolved type size. Preference changes use the same paint versus layout invalidation contract as theme changes, and type scaling also invalidates semantics. Hot color, elevation, contrast, and motion changes request paint; typography and geometry metrics request layout, paint, and semantics. Invalid scope and preference updates roll back atomically. The gallery switches between dark and light application themes while retaining the same button behavior and semantic identity; the light theme adds a leading-rail recipe so the change is structural rather than only a palette swap.

`AnimationClock` accepts absolute monotonic time and keeps one animation per node and `AnimationKey`. A new animation on the same key starts from the currently sampled value. A nonzero theme motion duration overrides the duration in `AnimationSpec`; a zero theme duration uses the spec duration. Reduced motion, zero duration, and equal endpoints complete synchronously. Advancing active animations emits values, dirties paint only, and reports whether the caller should schedule another OS frame. Removing a node cancels its animations on the next advance.

## Prototype acceptance scenarios

The shared gallery must demonstrate startup, an idle window, resize, a large scrolling list, a long multilingual document, live theme switching, and multiple windows. Benchmarks will record startup time, idle CPU and memory, resize latency, input-to-paint latency, scroll frame time, and build size on named machines. Release budgets will be set only after prototype measurements. This machine is an Apple silicon MacBook Pro running macOS 26.5; hardware model and measurement tooling still need to be recorded before baseline data is valid.

## Current implementation boundary

`choscorui-core` currently provides logical geometry, retained ownership, deepest, last-child-first hit testing, dirty tracking, focus identity, pointer-capture identity, and synchronous pointer/keyboard dispatch. Bounds are absolute logical points and ancestors clip descendants. Dispatch visits ancestors in capture order, the target, then ancestors in bubble order. `Stop` ends dispatch; a removed target cancels the remaining path. Nested dispatch completes before the outer event resumes. Keyboard events target focus; committed and marked text use a separate owned platform-event path. Focusable nodes traverse in depth-first child order with forward/reverse wrap; the gallery maps Tab and Shift-Tab to that traversal. Linear layout supports rows and columns, weighted flex with min/max, padding, spacing, cross alignment, and RTL row order. Grid layout adds fixed/flexible tracks, row/column spans, and RTL columns; form layout aligns measured labels beside flexible fields. These primitives reject unsatisfied minimum constraints without partially moving nodes. A scroll viewport clamps line/point offsets, translates its retained content subtree, relies on ancestor clipping for hit testing, and minimally reveals a requested content rectangle. Scrolling invalidates paint and semantics without remeasurement. The gallery uses linear layout and a 20-row scroll viewport. Intrinsic content-driven grid sizing, baseline alignment, direction inheritance, measurement caching, virtualization, and the remaining roadmap gates remain open.

`SemanticTree` projects semantic roles, localized names and descriptions, values, state, relationships, supported actions, current layout bounds, and focus from stable retained `NodeId` values. Its snapshot follows retained child order and connects semantic descendants through containers without semantic data. Updates identify the affected retained node for labels, values, state, and focus; combined value/state updates preserve identity. Removed nodes are pruned explicitly. Relationships must target another semantic node. Button, Checkbox, and TextField all export this shared contract; text fields include UTF-16 character count and selection ranges. The macOS backend reconciles snapshots into stable `NSAccessibilityElement` objects, converts bounds to screen coordinates, exposes hierarchy and relationship attributes, updates label/help/value/enabled/focused/selected-range properties, and posts AppKit layout/title/value/focus notifications. Native `AXPress`, focus, and editable `setAccessibilityValue:` callbacks queue retained-node requests consumed by the same control behavior, with bridge synchronization forwarded to the superclass without producing false edits. The gallery publishes its core controls, multilingual document, and twenty scroll rows through this bridge. Manual VoiceOver navigation across supported macOS versions remains in the phase 9 gate.

`TextBuffer` stores UTF-8 text and maps grapheme, byte, and UTF-16 boundaries explicitly. It supports grapheme-indexed selection replacement, forward/backward deletion, caret/word movement with selection extension, and text-only undo/redo that restore selection. It can return selected text, cut/paste in memory, and produce one mask glyph per grapheme for display. `TextField` connects this model to focus, committed text, provisional marked text, UTF-16 replacement ranges, navigation keys, edit/commit notifications, semantic value setting, invalidation, and a swappable visual recipe. Marked updates remain outside the buffer and undo history; commit or unmark produces one undoable edit, while explicit cancellation discards the provisional text. The gallery renders marked text and reports selection, marked range, and candidate-window caret geometry back to AppKit. Password mode retains the application-visible value while masking one glyph per grapheme in rendering and accessibility, publishing the AppKit secure-text subrole, returning no selected text, and rejecting cut. Valid, intermediate, and invalid state are separate from the edit buffer; only valid input commits, while invalid state exposes an announcement and visual error indicator. The gallery routes Command-A/C/X/V/Z/Shift-Z through the text-field seams and main-thread `NSPasteboard` text API. Input masks, locale-aware parsing, file/image clipboard formats, physical Vietnamese IME verification, and the complete phase 7 manual gate remain open.

`IntegerRange` provides overflow-safe clamped steps shared by `Slider` and `SpinBox`. Slider supports horizontal/vertical pointer dragging, capture, arrow/Home/End keys, and set/increment/decrement semantic actions. SpinBox exposes the same range actions through keyboard and pointer button regions. ProgressBar exposes read-only determinate percentages or indeterminate state. All three keep paint recipes separate from behavior, publish typed semantic roles, and invalidate paint plus semantics for value changes without forcing layout. Decimal spin boxes, editable numeric text, locale formatting, and indeterminate animation remain open.

`choscorui-windows` provides a Windows-only Win32 window shell plus portable translation tests for logical DPI coordinates, suggested frames, pointer/wheel/key events, UTF-16 surrogate ownership, focus, resize, and close. Its native layer cross-compiles for `x86_64-pc-windows-gnu` and includes class registration, top-level lifecycle, blocking/bounded pumps, worker posting, DPI updates, and panic containment. Direct2D/DirectWrite, clipboard, drag/drop, menus/dialogs, touch/pen, TSF IME, UI Automation, gallery wiring, and execution on Windows remain required before support is claimed.

`choscorui-linux` defines separate Wayland and X11 lifecycle contracts. Wayland requires global binding, initial commit, configure receipt, exact serial acknowledgement, buffer commit, and a single outstanding frame callback. X11 uses separate connect/create/map/configure state without Wayland acknowledgements. Shared contracts cover seat-gated input, key cleanup, backend capability discovery, and clipboard MIME ownership. Native protocol bindings, rendering/text stacks, portals, IME, AT-SPI, gallery wiring, and execution on Wayland and X11 remain required before support is claimed; see [Linux backend contract](LINUX.md).

`choscorui-compose` is the platform-independent Rust composition layer. An `Element` description uses a globally unique application key, logical bounds, focusability, and child descriptions. `Reconciler` validates a complete description before mutation, preserves retained `NodeId` values across sibling reorder and reparenting, updates declared properties, and removes keys absent from the next description. This preserves retained focus and control state when a keyed element remains. `Runtime` provides typed observable properties, one- and two-source derived values, one-way mapped bindings, batched propagation, final-value notifications, cycle rejection, and recoverable computation errors that retain the last valid value. Named states select the first matching condition and apply discrete or numeric assignments; exact and wildcard transitions animate numeric properties through `AnimationClock`, including interruption, reduced motion, cancellation, and removed-node cleanup. The graph is deliberately single-threaded and separate from platform event loops. A parser or separate declarative DSL is not justified at this foundation stage; Rust builders remain type checked and use the retained tree directly. Asynchronous components, dynamic loading, and a decision on a separate declarative runtime remain future work.

`choscorui-macos` now creates and owns an AppKit top-level window and exposes show, close, reopen, visibility, title, logical content size, and backing scale. Its `Application::run` and `stop` wrap the native event loop. `Poster` queues `Send` work FIFO from workers onto a Core Foundation source on the main run loop, contains callback panics, and can request loop stop safely. A window delegate queues owned resize, scale, focus, and close events in callback order. A custom flipped `NSView` translates mouse buttons, movement, wheel, keyboard navigation, repeat state, modifiers, and `NSTextInputClient` marked/committed text into owned events. It exposes selected/marked UTF-16 ranges and candidate-window geometry, accepts attributed or plain input strings, and uses a guarded ordinary-character fallback only when `interpretKeyEvents:` produced no text callback. Navigation/private-use characters and control characters stay out of committed text. Wheel deltas are positive toward right/down and retain `Points` for precise devices or `Lines` for coarse wheels; controls resolve line units using their own metrics. One-shot timers run on the UI thread, support cancellation, and contain callback panics. Repeating timers are still absent. See [FFI safety record](FFI.md).

`Application::dispatch_next_event` waits for one native event with a bounded timeout, forwards it through `NSApplication`, and lets callers drain owned window events afterward. The current gallery uses this path to exit on native close. Synthetic events sent through `NSWindow` reach the custom view during the native loop, and the bounded pump services posted work; physical device input still needs manual platform testing.

The renderer-neutral display list has ordered rectangle fills, nested rectangle clips, and owned single-line text commands in logical points with RGBA8 colors. The macOS `drawRect:` painter draws text through Core Text and rectangles through Core Graphics; the gallery displays button, checkbox, and row labels. `ShapedLine` provides Core Text advance/ascent/descent/leading, grapheme-indexed caret offsets, and nearest-caret hit testing; painting constructs this same shaped-line type. `WrappedText` uses Core Text contextual break suggestions, snaps breaks to whole graphemes, handles LF/CRLF, and emits lines at measured baselines. It maps lines to source grapheme ranges, hit-tests document points, and returns per-line selection and caret rectangles. The gallery supports pointer-drag selection with capture plus horizontal, vertical, word, start, and end keyboard movement with Shift extension. Vertical movement preserves its horizontal goal, keyboard movement reveals the caret, and capture cancels on focus loss. `MacBitmap` uses the window painter offscreen and returns premultiplied RGBA8 pixels in top-down rows; fixtures confirm glyph ink at 1x/2x and clip behavior. `choscorui-render` remains a software reference for rectangle fixtures and explicitly rejects text commands until it can render them. Its current source-over blend operates on sRGB channel values and is experimental. Rounded shapes, borders, images, cached shaped runs, software text output, color-space conversion, damage regions, mixed-direction selection geometry, and on-screen pixel comparison remain open.
